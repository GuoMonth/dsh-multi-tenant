# v0.3 P0 底座

v0.3 的目标，是把项目从 Multi-Tenant Runtime 推进为可组合 SaaS Framework 的基础。本文件先固定工程方法和 P0 边界，再扩张实现。

## P0 目标

P0 只回答三个架构问题：

1. **Composition** —— SaaS capability 如何声明、校验并映射到 Runtime scope，同时不再造第二套 DI Container。
2. **Operation** —— authenticated Principal 如何启动一次用户可见工作，并通过 Principal-derived lifecycle boundary 驱动 DSH Agent create / resume。
3. **Fail-fast validation** —— 非法 capability graph 如何在用户流量进入前失败，而不是等第一条 Agent 请求才报错。

Distribution、Marketplace、安装 UI、具体厂商 Auth、具体 MCP 集成、billing、audit、usage 产品都不是 P0。

## 强制开发顺序

所有 P0 功能都按下面顺序推进：

```text
Spec
  ↓
Assumption Ledger
  ↓
Executable external probe / contract test
  ↓
强类型 + 状态模型
  ↓
Failing behavior test
  ↓
最小实现
  ↓
Vertical-slice CI proof
```

只要某个 public API 依赖的 blocking external assumption 在 `v0.3-assumptions.json` 中还是 `open`，这个 public API 就不能定型。

## Evidence 分类

- **External probe** —— 在精确支持版本上证明 DSH / Cordis 拥有的行为。
- **Contract test** —— 独立于具体生产实现，证明仓库自己拥有的可替换 seam。
- **Conformance test** —— 证明 isolation、publication ordering、teardown 等跨组件 invariant。
- **Vertical slice** —— 证明真实 Principal -> Operation -> DSH 路径。

读 upstream source 适合发现 hypothesis，但不能替代 blocking assumption 的 executable proof。

## P0 架构边界

```text
SaaSDefinition
      ↓ normalize
CompositionPlan       immutable、已校验、无未解析歧义
      ↓ bootstrap
Tenant / Principal capability graph
      ↓
Principal Operation
      ↓
DSH ownerCtx / Agent setup-publication seam
```

Composition 层只负责 selection、scope placement、dependency validation 和 bootstrap ordering。Service resolution、injection、Fiber lifetime、cleanup 继续由 Cordis 负责。

**禁止新增第二套 ServiceRegistry / ProviderContainer / generic DI resolver。** 如果设计开始复制 Cordis，说明抽象方向错了。

## Package 规则

这个 foundation PR 不创建任何新的 v0.3 package。只有实现真正证明了独立 consumer API、replacement boundary、lifecycle/composition boundary、version/release boundary 或 Distribution boundary，package 才能出现。

Auth、Credentials、MCP、Transport 这些 capability 名称默认都不是 package 名称。

## P0 Promotion Gate

一个 P0 abstraction 只有满足以下条件才能成为 public API：

- ownership / state model 已有 Spec；
- 依赖的所有 blocking external assumption 都是 `proven`；
- 非法配置有语义化 fail-fast error；
- Tenant A/B 与 Principal sibling isolation 有覆盖；
- teardown / cancellation 行为有覆盖；
- Principal -> Operation -> DSH vertical slice 在 CI 可执行。

## 当前刻意保持 Open 的 Gate

Cordis `ctx.inject()` 是 dependency-reactive 的。required service 消失并恢复时，它可能 unload 并重新执行 callback。这对长期 plugin 很合理，但如果 callback 被当成 exactly-once 用户工作，就可能危险。

因此，在我们证明一个不会因为 provider churn 重复产生外部可见工作的 one-shot dependency acquisition / lifecycle 模型前，最终 Operation API 保持 blocked。参见 assumption `A6` 与 [`operation-lifecycle.zh-CN.md`](./operation-lifecycle.zh-CN.md)。
