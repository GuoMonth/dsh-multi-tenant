# dsh-multi-tenant 0.4.0-alpha.1

This alpha resets the project to one job: provide Principal-scoped DSH Agent resources for multi-tenant hosts.

## Delivered

- server-minted, runtime-verifiable `PrincipalContext` and plugin-generated opaque `AgentId`;
- SQLite Agent directory with scoped queries, CAS revisions, failure states, restart support, and scrubbed tombstones;
- DSH alpha.4 Agent create/resume and official Agent-scoped MCP setup with raw logical server names;
- in-memory secret leases with revision, revocation, and disposal;
- replaceable runtime partition protocol with fail-closed minimum isolation;
- controlled `withAgent()` execution view and serialized/single-flight lifecycle;
- authenticated Agent CRUD on the existing DSH Web server;
- contract, Web, concurrency, restart, real MCP, packed-consumer, and Node 22.19/24 evidence.

## Retrospective

The earlier architecture assumed APIProxy/stock Web interception, caller-selected Session ownership, globally rewritten MCP namespaces, and general composition/capability/operation frameworks. DSH alpha.4's native Agent setup and Agent-scoped MCP lifecycle make those structures unnecessary. They were removed instead of adapted; sunk cost did not constrain the design.

The stable core is now a small authority kernel around `PrincipalContext -> AgentId -> owned DSH lifecycle`. Properties the plugin cannot create honestly remain protocols: host authentication, secret authority, multi-replica persistence, and strong runtime isolation.

## Explicit limits

- The default provider is logical same-process isolation, not a hostile-code boundary.
- SQLite is local/single-node; it is not a distributed ownership service.
- Typert public ingress is absent because stock Typert has no trustworthy Principal binding.
- Stock DSH `/api` is private/administrative.
- Agent deletion revokes plugin access and scrubs its directory record; it does not claim physical erasure of DSH logs.
- No `0.3` API or data migration is provided.

This release note records the `0.4.0-alpha.1` milestone review. No npm publication or GitHub Release is implied by the local release-ready state.

## 中文复盘

本轮目标是把项目收敛回一个职责：为多租户宿主提供 Principal-scoped DSH Agent 资源。最终交付与目标一致：可信 `PrincipalContext`、opaque `AgentId`、SQLite Agent Directory、DSH alpha.4 原生 Agent/MCP 生命周期、Secret lease、隔离协议、受控运行入口和认证后的 Web CRUD 都已有可执行证据。

被推翻的旧假设包括：依赖 APIProxy/stock Web 拦截、让调用方选择 Session 并把它当 authority、为规避全局 MCP name 冲突而哈希命名，以及预先建立通用 composition/capability/operation 框架。alpha.4 的 unpublished Agent setup 和 Agent-scoped MCP 已经提供更自然的生命周期边界，因此旧结构全部删除，沉没成本没有进入决策。

明确限制保持不变：默认 shared provider 只有同进程逻辑隔离；SQLite 只承诺 local/single-node；没有可信 Principal 绑定前不提供 Typert 公网入口；stock DSH `/api` 仅限私有/管理用途；删除不宣称物理擦除 DSH log；不提供 `0.3` 迁移。

下一 milestone 建议为 `0.4.0-alpha.2`，只处理运行证据暴露出的窄风险：进程崩溃后的 stale provisioning reconciliation，以及宿主 Secret/RuntimePartition provider 的公开 conformance harness。它不恢复旧框架，也不扩大为独立 control plane。
