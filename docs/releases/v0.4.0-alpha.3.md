# dsh-multi-tenant 0.4.0-alpha.3

Release posture: **DSH RC compatibility rebaseline**. This release keeps the alpha.2 product surface, repository schema, authority model, and runtime behavior unchanged while moving the only supported Harness baseline to `0.1.2-rc.1` at commit `a66e4702047846cdaa10c66c9d3df3951f5ea70d`.

The matching source tag is `v0.4.0-alpha.3`. npm distribution belongs on the `alpha` dist-tag and must not move `latest`; npm publication, the source tag, and a GitHub prerelease remain separately verifiable distribution operations.

## DSH RC baseline

The official [alpha.5-to-RC.1 comparison](https://github.com/deepseek-ai/deepseek-harness/compare/dsh-v0.1.2-alpha.5...dsh-v0.1.2-rc.1) is two release commits ahead and changes only package version metadata. No Agent registry/loop, Session, persistence, Session projection, MCP client, Tools, Cordis integration, or API/Web source changed in that delta.

All DSH packages used directly by production code or executable lifecycle evidence are nevertheless pinned exactly to `0.1.2-rc.1`. CI independently checks out the release commit and verifies its root package version, so the npm graph and reviewed source identity advance together.

## Compatibility decision

Published alpha.2 remains the immutable pairing for DSH `0.1.2-alpha.5`. Alpha.3 supports DSH `0.1.2-rc.1` only. It does not add a dual-version peer range, silently accept later RCs, or rewrite the already published alpha.2 artifact and tag.

This is a compatibility-only plugin release. There is no public API addition, SQLite migration, runtime policy change, Web behavior change, or new security claim. Host providers written for alpha.2 retain the same required lifecycle-signal contracts.

## Evidence

The release contract covers frozen installation, exact peer/development dependency consistency, Node 22.19 and Node 24, type declarations, all unit/contract/Web tests, the native DSH AgentLoop + JSONL + official MCP create/restart/resume/delete lifecycle, SQLite restart and permission probes, and an installed-tarball consumer. CI separately proves that the pinned upstream commit reports version `0.1.2-rc.1`.

## Explicit limits

- The built-in SQLite directory remains local, single-node, and host-guaranteed single-active-process.
- The bundled runtime provides logical isolation, not a hostile-code boundary.
- Authentication, secret storage, and the truth of a strong-isolation provider remain host responsibilities.
- Stock DSH `/api` remains private/administrative; there is no public Typert ingress.
- Delete does not physically erase DSH logs, and cooperative shutdown cannot force unresponsive host code to stop.
- `0.3` data and prior unpublished candidate schemas are not migrated.
