# v0.7.0 — Principal-isolated native Hosts

This breaking source release replaces the shared-Host Cordis plugin, per-Agent authority facade and custom Web panel with a platform directory, runtime coordinator and authenticated native HTTP/WebSocket ingress. There is no automatic legacy data migration. Publication remains a separate manual release action.

The authority unit is `(tenantId, principalId)`. DSH owns all sessions, workspaces, presets and native permissions inside that domain; independent root read ACLs are not promised. Platform administration remains outside native Hosts.

Public consumers import `SQLiteDomainRepository`, `DomainRuntimeCoordinator`, `createDomainIngress`, runtime providers and authentication interfaces from `dsh-multi-tenant`. The native control asset has a separate export. Old `/mcp`, `/web`, `/starter`, `/deliveries`, `/sqlite`, `/testing` and Cordis bundle entrypoints are removed. DSH is installed inside the native runtime, not as platform peers.

The included Docker provider is an offline Linux reference: fixed image identity, no network, non-root, read-only root/profile, separate domain data, resource limits and inode-pinned private transport. The local process provider is trusted development only. Deployments needing remote models/MCP must provide an explicitly reviewed network-capable runtime provider.

Validation uses an installed tarball and exact DSH 0.1.5-rc.2, source `fb2c4b9e698e30edb738bca4cf0618587db7d203`. See the current refactor plan and WP5 evidence for commands, coverage and limits. No root-level revocation claim or shared-Host multi-user support is inferred from the native integration tests.
