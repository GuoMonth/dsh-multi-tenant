# 企业内网持久 AI 工作环境

2026-09-29 产品定位。本文定义目标与取舍，不宣称当前 Alpha 已具备企业容量、备份恢复或升级能力。实施和验收以 [主线 #104](https://github.com/GuoMonth/dsh-multi-tenant/issues/104) 为准；资源接口见 [AgentEnvironment 设计](agent-environment.zh-CN.md)。

## 目标人群与价值

面向在企业内部部署 AI 工作环境的组织：总人数一般不超过 5 万，同时在线最多 5000。员工包括需要处理文件、分析数据、执行工具和开发任务的业务人员与开发者；管理员是负责企业身份、基础设施和数据的 IT／运维人员。优先支持已有 Kubernetes、OIDC 和存储运维能力的企业，不把“简单配置”表述成无需基础设施或运维。

员工用企业账号进入自己的空间，持续使用文件、对话和工具；管理员通过少量配置完成准入、资源控制和数据保护。用户不需要理解 Sandbox、Cell、Pod、PVC、namespace 或两仓库的分工。对外呈现一个产品和安装入口，内部保持平台与运行时模块边界。

优先级：数据与归属可靠 → 使用和运维可理解 → 配置与接入省事 → 资源成本可控 → 启动速度。允许秒级进入、受控维护停机和过载时明确等待；不为毫秒级启动引入额外平台。可接受性能取舍，不牺牲访问隔离、凭据保护或故障真实性。

主要差异化是交付完整企业工作闭环，而非独占某项 Sandbox 技术。上游已有持久化与隔离能力；本项目承担身份接入、员工体验、受控配置、数据恢复及可复现交付。

## 少概念的使用体验

- 员工：企业登录 → 进入工作空间 → 使用原生 DSH。下次进入能找到已保存的文件、对话与配置；必要的重新授权有明确说明。
- 管理员：配置企业身份、模型服务、域名/TLS、存储/备份和默认额度；日常操作是准入/撤权、查看用量与故障、维护和恢复。
- 成员同步不预分配计算和卷；首次使用才受控开通。不要求管理员手工创建每用户 namespace 或提交任意 PodSpec，不增加用户侧模板市场与运行后端选择。
- 页面关闭、退出登录和撤权不等于环境空闲。显式停止说明会中断后台任务；不能用未经验证的自动 idle 误杀工作。
- 容量不足时给出可取消的等待或明确拒绝；出现缺卷、身份冲突、恢复失败时保留现场，不创建空白空间伪装成功。

## 复用成熟能力

| 需要 | 默认方向 | 本项目负责 |
| --- | --- | --- |
| 环境生命周期 | 已选定 agent-sandbox core + Kubernetes 普通 Pod | 薄适配、精确归属、启停与访问一致性；不 fork、不套同义 CRD |
| 企业登录 | 现有 OIDC 身份提供方 | 成员映射、准入、撤权；不自研身份目录 |
| 安装与升级 | Helm 作为优先实现路径，固定组件版本 | 一套受支持配置、预检、明确升级步骤；不自研安装平台 |
| 持久性与备份 | 经验证 CSI/存储服务 + 企业现有备份，必要时采用 Velero 等成熟工具 | 确定数据范围、一致性和密钥策略，实际恢复演练；不自研备份引擎 |
| 网络与资源控制 | 既有 CNI、Kubernetes quota/limits、企业模型网关 | 安全默认值、少量业务配置和可解释的容量限制 |
| 模型、工具和应用 | 原生 DSH + 选定真实工具 | 接入验证和持久配置，沿用原生应用协议 |

已选定 agent-sandbox core 的有限试验不等于生产接入。Helm 交付和备份参考方案仍待实现/验证；Velero 是候选，不代表任意 CSI、数据库或密钥方案开箱即用。先支持一条完整的参考组合，再按真实部署需要扩展。平台不新增通用 Secret/Vault 服务或 OAuth 刷新代理。

## 数据承诺与职责

“数据不丢”必须标注故障范围和恢复目标。正常操作保存数据；事故通过经过演练的备份恢复。未落盘内存、尚未保存内容和被中断任务的自动续跑不在承诺内，也不承诺所有灾难零损失。

| 场景 | 企业交付要求 |
| --- | --- |
| 断网、退出、停止、Pod 重建 | 已保存文件、对话和必要配置保留，重新进入可继续使用 |
| Agent 误删/改坏文件 | 有受支持的历史版本或备份恢复路径；最近备份后的变更受 RPO 约束 |
| 环境损坏、存储故障 | 明确支持的恢复范围、目标存储和操作步骤，实际演练 |
| 升级镜像或产品版本 | 已验证的版本对和受控停机流程，默认承接个人数据；失败处理明确 |
| 员工离职、撤权、卸载 | 撤销访问、保留/移交数据、销毁凭据、永久清除分别处理，不默认级联丢失工作 |

数据范围包括工作文件、DSH 持久状态、必要 HOME/工具配置、平台身份/归属绑定与恢复所需密钥。private 卷可能包含用户安装的软件和配置，不应被当作只有 token 的可丢弃缓存。凭据须有加密、权限和保留策略；无法恢复的外部授权应提示重新授权。

平台负责端到端恢复后的用户归属与访问正确性；runtime 负责停止证明、卷绑定、重建和受控维护；存储/备份系统负责副本和恢复机制；管理员负责凭据及备份目的地配置，并执行演练。不能只备份卷而遗漏映射或密钥，也不能把 PVC Retain 或同故障域快照当成完整备份。

RPO（允许丢失的最近数据时间窗口）与 RTO（恢复耗时目标）由参考部署实测和业务确认，当前不编造数值。未确定并演练前，不能声称企业数据保障已验收。

当前 Alpha 的不兼容边界保留为历史事实。企业版本至少支持明确的相邻版本升级路径，不承诺任意历史版本兼容；从旧 Alpha 迁移可人工操作，但要说明保全/导出办法。普通请求仍禁止按新 UID 自动认领旧卷；维护流程需停止证据、归属校验、备份和显式绑定变更，不能靠重建空卷实现“升级”。

## 容量与性能边界

5 万成员和 5000 在线是产品目标，不是当前测试结果。目录成员、开通用户、在线连接、运行环境、正在执行的 Agent 分别计数。不能按 5000 条连接推导出支持 5000 个同时执行的任务，模型网关吞吐另计。

1—5 秒进入是可接受体验方向。候选基线是在参考硬件、镜像已存在、卷已创建且容量充足时，正常唤醒端到端 P95 ≤ 5 秒；待实测后确定正式门槛。首次创建、镜像冷拉、集中进入和故障恢复单列，不拿 API 返回或 Pod Running 作为可工作时刻。小样本已有约 10.8 秒首次、6.6 秒热启动证据，不能冒充达到新目标。

优先优化常驻内存、受控并发、存储挂载、Kubernetes API 访问和峰值排队。按成员数预分配全部资源不可取；计算可停止，数据生命周期独立。平台单副本可作试用方案，企业参考部署的重启影响、连接恢复与必要冗余要验证，不默认等同高可用。

不以热池、microVM 快照、内存恢复、多集群或多后端作为首批门槛；无可靠活动信号时不建设自动 idle。普通 Pod 不等于对敌对代码的绝对安全保证，内部员工也可能执行不可信依赖；保留非 root、最小权限、网络限制、资源额度和凭据边界。

## 参考

- [Agent Sandbox](https://github.com/kubernetes-sigs/agent-sandbox)：复用 core 生命周期与持久工作负载能力。
- [OpenSandbox](https://github.com/opensandbox-group/OpenSandbox)：通用运行能力的参考，本项目不为追齐功能切换底座。
- [Helm charts](https://helm.sh/docs/topics/charts/)：标准部署打包；具体版本另行固定。
- [Kubernetes PV 回收](https://kubernetes.io/docs/concepts/storage/persistent-volumes/#reclaiming)、[CSI snapshots](https://kubernetes.io/docs/concepts/storage/volume-snapshots/)：持久资源与快照的真实边界。
- [Velero](https://velero.io/docs/main/)：备份恢复候选；存储、应用一致性和加密仍需组合验证。
