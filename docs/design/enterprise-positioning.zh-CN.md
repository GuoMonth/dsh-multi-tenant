# 开源 Alpha：企业内网持久 AI 工作环境

2026-09-29 用户最新裁决：先完成简单够用的 MVP，直接做破坏性变更。当前验收以 [Issue #104](https://github.com/GuoMonth/dsh-multi-tenant/issues/104) 为准，执行分工见 [MVP 准备与波次计划](../plans/mvp-rc2.zh-CN.md)。本文是目标，不是已实现能力。

## 唯一首版闭环

管理员按一份说明在已有 Kubernetes 上安装；员工通过企业 OIDC 登录，首次进入自动开通自己的环境，使用原生 DSH。停止、启动和正常 Pod 重建后，文件、会话和工具配置仍在；不同用户不能互访，撤权立即关闭访问。

面向具备 Kubernetes、OIDC、DNS/TLS 与存储运维能力的组织。一个集群、平台单副本、一套 Linux/amd64 参考配置足够。用户只看到登录、进入、停止、启动及可理解的失败提示；不需要理解 Sandbox、PVC 或 namespace。

## 首版范围

- 固定 DSH `0.2.0-rc.2` 与源码提交 `639ed015397290b3745d163aafe02ffee4aa3f84`。本轮不跟随浮动 latest/next；对齐版本不等于接入它的全部新功能。
- 只使用 Kubernetes 与已选定 agent-sandbox core；不 fork、不叠加同义 CRD、第二控制器、独立 runtime 服务或多后端抽象。
- 平台负责 OIDC/准入/归属绑定与访问；runtime 负责模板/单卷绑定/生命周期与受限连接；DSH 负责原生对话、工具、插件、模型和应用状态。
- 每用户一个 AgentEnvironment、一个 PVC。固定挂载 `/var/lib/dsh/data`，下设 `workspace/`、`home/`、`dsh/`；HOME 与 DSH_HOME 分离。可配置的缓存放 `/tmp`，不为迁移所有上游内部缓存修改 DSH。
- CPU/Memory 使用原生 requests/limits；存储只有一个每用户容量配置。提供默认值，真实硬限制由参考存储验证。容量不足明确失败；不建 min/max 存储机制、目录配额、自动扩容、计费、用量平台或排队系统。
- 首次使用通过受限管理路径按固定模板供应资源，不让管理员逐用户手工建 namespace，不把集群凭据放进用户环境。
- 一套安装路径，优先 Helm；引用管理员已有 Secret。固定配套镜像与包版本，不要求校准 PodSpec。第二操作者安装与 W3 联合验收共用同一份证据。
- 真实模型、文件操作、命令执行和至少一条真实外部工具授权链通过；不承诺任意 MCP/CLI/插件兼容，不接入桌面特有能力。

## Alpha 破坏性变更

不维护旧 Cell、旧后端、旧 API/配置/状态格式、旧版本升级路径、迁移工具、双模式或兼容层。使用全新测试环境和数据验证新版本即可；历史版本不构成本轮工作依赖。已发布制品与历史证据保持原事实，无需追补。

该决定允许删除旧实现，不要求也不自动执行旧集群、其他任务资源或既有用户数据清理。新版本自身仍必须保证正常停止/重建不静默丢数据、缺卷不新建空卷、owner/UID 精确核验。永久清除用户数据是独立明确操作。

## 明确后置

完整备份恢复、相邻版本升级及 RPO/RTO 由 [#112](https://github.com/GuoMonth/dsh-multi-tenant/issues/112) 后续评估，不阻塞本轮 MVP；首版不宣称灾备保障。有需要时复用成熟工具和企业已有存储，不捆绑 RustFS/MinIO 或自研备份系统。

5 万成员/5000 在线、5 秒唤醒指标与容量成本目标由 [#113](https://github.com/GuoMonth/dsh-multi-tenant/issues/113) 后续实测。MVP 仅报告两用户和小规模实测结果，不以未来规模阻塞交付。

HA、多集群、热池、自动 idle、内存恢复、节点分区 fencing、通用迁移、容量仪表盘、自动扩缩容与高级工具集成均后置。未知结果明确失败并保留诊断，不构建无限自动恢复。

## 首版完成证据

1. 干净参考环境由第二操作者仅按文档安装，无维护者手工校准。
2. 两个真实 OIDC 用户各自进入并使用原生 DSH；HTTP/WS 与凭据隔离、退出撤权通过。
3. 一条真实模型与外部工具链完成任务，HOME 配置和授权在正常停止/启动后保持或明确要求重新授权。
4. 文件和会话在 Pod 重建后仍可读；缺卷/替换卷/错 owner 拒绝，停止不确定时不再启动第二 writer。
5. CPU/Memory、配置容量、容量不足与小规模启动性能有实测；不以 local-path 的申请容量宣称硬配额。
6. 双仓库 commit、DSH commit、controller/workload/platform 镜像及包版本形成一个可复现组合；发布前所有失败与未覆盖项明确。

安装 #111 与 W1/W2/W3 构成 MVP；#112/#113 不属于其关闭条件。源码存在、文档完成和旧版测试通过均不代表新组合验收。
