# Release procedure

The user authorizes publication after strict local validation. npm and the matching GitHub Release use one version and a lightweight `vVERSION` Git tag. The paired runtime has its own version and an explicit cross-link. Never move an existing tag or overwrite an npm version.

1. In both repositories run the manifest-pinned checks. Platform: `pnpm install --frozen-lockfile && pnpm release:check`; runtime: `make verify` and `make verify-dsh` with its pinned Go/Node tools. Keep root/package READMEs identical and AI guide links versioned.
2. Review and merge sources. Run each repository's manual `prepare-release.yml` on main. These build candidate images and preserve exact image digests/source metadata; platform also preserves its reviewed npm archive. They do not publish npm or create a Release.
3. Download both candidate artifacts. Verify tarball integrity, anonymously pull the exact images and perform local installation/native two-user/model/tool/lifecycle/negative acceptance on that exact combination. Preserve credentials privately; save a redacted validation report. Do not rebuild the accepted package for publication.
4. Create the runtime lightweight tag and GitHub Release at its verified commit, attach candidate/validation metadata and link the platform version. Keep the internal Connector private.
5. Dispatch platform `release.yml` on the exact prepared main commit with both run IDs, locally verified npm integrity, workload digest and runtime tag. It checks successful preparation/source identity and paired runtime tag, downloads the exact archive, publishes through the existing `npm-release` Trusted Publisher, verifies registry bytes and `latest`, then creates the lightweight tag and matching GitHub Release with manifest/checksums/archive. Attach the local validation report.
6. Verify registry installation, public image pulls, both GitHub releases, lightweight tag objects and cross-links. Then close acceptance Issues and clean completed workspaces without deleting user PVCs or private evidence.

GitHub Actions needs Node24/npm>=11.5.1, `id-token: write`, workflow `release.yml` and environment `npm-release` matching npm Trusted Publishing. No local npm token is needed. If publication partially succeeds, rerun only the same source/candidate: the script verifies existing npm integrity before continuing. Registry/network failures are not proof of absence. Correct a mismatched source or artifact rather than retrying with a new payload under the same version.

Registry acceptance can precede public metadata availability. Poll fresh version metadata for up to 15 minutes; if that still times out, verify registry visibility and rerun the same workflow attempt with the same candidates. Do not dispatch a rebuilt archive or bump the version to work around delayed visibility.
